# For AI agents working in this repository

Pocket Scribe files voice recordings (from a Pocket recorder, or voice messages
sent to a Telegram bot) into a person's own trackers, on their own Cloudflare
account. Everything runs in the accounts of the person you're working with;
nothing is shared with whoever made the repository. README.md explains how it
works.

## Setting it up for someone

Follow **SETUP.md** from the top, one step at a time.

- **Stop at every Check.** Run it, show the person the result, and only go on
  when it passes. Later steps assume earlier ones worked, so building on a
  failed step makes things worse.
- **Some steps only the person can do:** creating accounts (Cloudflare,
  Anthropic, Telegram via @BotFather), clicking through dashboards, creating
  the Cloudflare API token, and copying keys. Tell them exactly what to click,
  as SETUP.md does, then wait for them to say it's done.
- **Step 4 is theirs to decide.** Show them the tracker menu
  (`npm run trackers`) and ask which they want. If they describe one that
  isn't on the menu, write it into `schema.json` following "Editing the
  schema" in SETUP.md, modelled on the menu's files in `trackers/`, then run
  `npm test`.
- When something fails, read the Troubleshooting table in SETUP.md before
  improvising a fix.

## Keys and secrets

- **Never ask for a key or token in chat, and never print one.** The person
  puts each value into `.env` themselves, in an editor. If they can't paste
  into the file, have them copy the value and run
  `printf 'KEY=%s\n' "$(pbpaste)" >> .env` on a Mac, or the equivalent on
  their system, so the value never passes through you. Don't `cat .env`; check
  that a line is set with `grep -c '^KEY=.' .env`.
- `npm run secrets` copies the keys from `.env` to the Workers. It is the only
  way they should get there.
- Cloudflare: the repository talks to exactly one account, with the token in
  `.env`. Before any wrangler command that calls the API (deploy, secret, d1,
  kv, tail), run `npx wrangler whoami` and check that it says *API Token* and
  lists the `CLOUDFLARE_ACCOUNT_ID` from `.env`. If it doesn't, stop and say so.
  Never `export CLOUDFLARE_*` in a shell profile, and never run
  `wrangler login` to get around an authentication error: an error with code
  10000 almost always means the token in `.env` is missing or lacks a
  permission row from SETUP.md, Step 2.

## Their files and the shared ones

- **The person's own files, untracked by git:** `.env` (keys and ids),
  `schema.json` (their trackers), `wrangler.jsonc` and `wrangler.app.jsonc`
  (generated by `npm run config` from the `*.template.jsonc` files plus
  `.env`), and `backups/` (their journal). Never commit them, and never put
  their ids or data into a tracked file.
- To change a Worker setting for everyone, edit the template. To change an id,
  run `npm run setup` (it records ids in `.env`).
- **Getting updates:** `npm run update`. It stops if shared files have local
  changes. In that case, explain what changed and let the person decide whether
  to keep or discard their edits before merging.

## Changing things

- After editing `schema.json` or the code: `npm test`, then `npm run deploy`
  (capture Worker) and `npm run deploy:app` (app).
- Don't delete the D1 database, KV namespace, R2 bucket or Access application:
  they hold the person's journal and its history. `npm run restore` replaces
  the whole database, so take a backup (`npm run backup`) first and run it
  without `--yes` to see what it would do.
